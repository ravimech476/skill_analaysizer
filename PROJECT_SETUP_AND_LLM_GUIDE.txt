1. PROJECT OVERVIEW
================================================================================

Skills Analyzer is a college placement and skills management platform that:
- Tracks student marks, skills, and attendance
- Analyzes student strengths/weaknesses from mark history
- Matches students to placement drives based on skills and eligibility
- Predicts career paths and recommends learning resources
- Provides interview question bank and study materials
- Sends notifications to eligible students for placement drives
- AI Chat Assistant (via Ollama LLM + RAG) for personalized guidance
- Aptitude testing with timed attempts and automatic scoring
- Communication and soft-skills assessment (self-report + staff rubric)
- Psychometric profiling (personality, interests, learning style)
- Career fit analysis (Holland codes, personality traits, coding relevance)
- Placement prep plans with project ideas and growth outlook
- Student insight (overall reading) — AI-generated summary per student
- Data quality reports for administrators
- Faculty risk alerts with score history tracking
- Bloom's taxonomy classification for question bank
- Skill suggestions from marks (LLM-proposed, staff-approved)
- Knowledge base with vector embeddings for semantic document search

Three applications:
- Go Backend API (port 8080)
- React Web Dashboard (port 5180)
- Flutter Mobile App (Android/iOS/Web)

2. TECHNOLOGY STACK
================================================================================

Backend:
  - Language: Go 1.27+
  - Framework: Gin (HTTP router)
  - Database: PostgreSQL 16+
  - Driver: pgx/v5 (connection pooling)
  - Auth: JWT (access + refresh tokens) + OTP (SMS)
  - File Storage: Local disk with signed URLs

React Web:
  - React 19 + TypeScript 6
  - Build Tool: Vite 8
  - UI Library: Ant Design 6
  - State Management: TanStack React Query v5
  - HTTP Client: Axios

Flutter Mobile:
  - Flutter 3.47+ / Dart 3.13+
  - HTTP Client: Dio
  - State: Provider
  - Token Storage: flutter_secure_storage
  - File Picking: file_picker, image_picker

LLM (AI Chat + Embeddings):
  - Ollama (local LLM server)
  - Chat Model: llama3.2 (8B) — generates answers, insights, Bloom's levels
  - Embedding Model: nomic-embed-text — converts text to vectors for
    semantic search in the knowledge base
  - Approach: RAG (Retrieval Augmented Generation)

12. OLLAMA LLM SETUP
================================================================================

Ollama is a local LLM server. It runs open-source AI models on your machine
without sending data to the cloud. All data stays private.

Step 1: Install Ollama

  Windows: Download from https://ollama.com/download/windows
  Linux:   curl -fsSL https://ollama.com/install.sh | sh
  macOS:   Download from https://ollama.com/download/mac

Step 2: Pull BOTH required models

  # Chat model — generates answers, insights, Bloom's levels, skill suggestions
  ollama pull llama3.2

  # Embedding model — converts text to vectors for knowledge base search
  ollama pull nomic-embed-text

  Both models are REQUIRED for the full feature set. Without nomic-embed-text,
  the knowledge base search will not work (chat still functions using
  database-only RAG, but without document retrieval).

  Alternative chat models (if hardware is limited):
  # For 4-8GB RAM (faster, smaller)
  ollama pull phi3

  # For 16GB+ RAM (best quality)
  ollama pull llama3.1

Step 3: Test Ollama

  ollama run llama3.2 "Hello, what can you help with?"

Step 4: Verify API is running

  curl http://localhost:11434/api/tags
  # Should list both llama3.2 and nomic-embed-text

Step 5: Verify embedding model

  curl http://localhost:11434/api/embeddings -d '{"model":"nomic-embed-text","prompt":"test"}'
  # Should return a JSON object with an embedding array

Ollama runs on port 11434 by default.

Hardware Requirements:
  Minimum: 8 GB RAM, any CPU (slow but works)
  Recommended: 16 GB RAM, 4+ CPU cores
  Best: 16 GB RAM + NVIDIA GPU (fast responses)

Which features use which model:
  llama3.2 (chat model):
    - AI chat assistant answers
    - Student insight (overall reading) generation
    - Bloom's taxonomy level suggestion
    - Skill suggestion from marks
    - Subject-to-skill mapping suggestions

  nomic-embed-text (embedding model):
    - Knowledge base document indexing (chunking + vectors)
    - Semantic search when answering chat questions
    - Study material / interview / question bank AI indexing

13. RAG (Retrieval Augmented Generation) — HOW IT WORKS
================================================================================

RAG means: instead of training the LLM on your data (expensive, complex),
you SEARCH your database for relevant information and SEND it to the LLM
along with the user's question. The LLM reads your data and gives a
personalized answer.

Flow:
  1. Student asks: "What skills do I need for TCS?"
  2. Backend searches database:
     - Finds TCS placement drives → required skills: Aptitude ≥3, Java ≥2
     - Finds student's skills → Aptitude (4★), Communication (3★)
     - Finds recommended courses → "Java Fundamentals on NPTEL"
  3. Backend searches knowledge base (vector similarity):
     - Finds relevant KB passages about TCS interview tips, roadmaps
  4. Backend builds a prompt:
     "You are an educational assistant for [College Name].
      Student: Arun Kumar, CGPA 7.8, CSE department.
      Student skills: Aptitude (4/5), Communication (3/5).
      TCS drive requires: Aptitude ≥3, Java ≥2, Communication ≥3.
      Available courses: Java Fundamentals (NPTEL, free, 40 hrs).

      [Knowledge base passages about TCS placed here]

      Student question: What skills do I need for TCS?

      Give a personalized, helpful answer."
  5. Sends to Ollama → gets a natural language response
  6. Returns to the student in the chat UI with source citations

What data gets searched (from YOUR database):
  - Student profile (CGPA, department, skills, marks)
  - Placement drives (company requirements, required skills)
  - Interview questions (practice questions by company)
  - Study materials (notes, resources per subject)
  - Career matches (career recommendations)
  - Courses (learning path recommendations)
  - Question bank (previous year questions)
  - Attendance records
  - CO/PO mappings (curriculum alignment)
  - Knowledge base documents (uploaded syllabi, notes, roadmaps — via embeddings)
  - Built-in knowledge content (career paths, industry skills, domain knowledge)

No training required. No cloud API costs. Data stays on your server.

14. CHAT MODULE IMPLEMENTATION
================================================================================

The AI Chat module is implemented in 3 layers:

--- BACKEND (Go) ---

Module: backend/internal/modules/chat/chat.go

Endpoints:
  POST   /api/v1/chat           — Send a message, get AI response
  GET    /api/v1/chat/history    — Get chat history for the user
  DELETE /api/v1/chat/history    — Clear chat history

How it works:
  1. Receive student's question
  2. Identify the student from JWT token
  3. Extract keywords/intent from the question
  4. Query relevant database tables based on intent:
     - "TCS" → search placement drives, interview questions for TCS
     - "skills" → fetch student's skills, career matches
     - "marks" → fetch mark history, strengths/weaknesses
     - "prepare" → fetch study materials, courses, question bank
  5. Search knowledge base (vector similarity via nomic-embed-text)
  6. Build a prompt with:
     - System instructions (you are an educational assistant)
     - Student context (profile, CGPA, skills, marks summary)
     - Retrieved database data (relevant to the question)
     - Knowledge base passages (semantically matched)
     - Conversation history (last 6 messages for follow-up context)
     - The question itself
  7. Call Ollama API:
     POST http://localhost:11434/api/generate
     Body: { "model": "llama3.2", "prompt": "<built prompt>", "stream": false }
  8. Save the answer with source citations
  9. Return the response to the frontend with sources

Concurrency: A semaphore limits to 2 simultaneous model calls (local models
are slow and memory-hungry). Additional requests wait.

--- FRONTEND (React Web) ---

A chat widget (floating bubble, bottom-right corner):
  - Opens a chat panel
  - Shows conversation history
  - Text input + send button
  - Displays AI responses with markdown formatting
  - Shows "typing..." indicator while waiting
  - Shows source documents cited in each answer

--- FRONTEND (Flutter) ---

A chat screen:
  - Accessible from the sidebar or a floating button
  - Same chat functionality as web
  - Uses the same POST /api/v1/chat endpoint

--- ENVIRONMENT CONFIG ---

Backend .env:
  OLLAMA_URL=http://localhost:11434
  OLLAMA_MODEL=llama3.2
  # OLLAMA_TIMEOUT=3m
  # OLLAMA_EMBED_MODEL=nomic-embed-text

--- PROMPT TEMPLATE ---

The system prompt is:

  "You are EduSkill Assistant, an AI educational advisor for [College Name].
   You help students with:
   - Understanding their academic performance
   - Identifying skill gaps for placement
   - Recommending courses and study materials
   - Preparing for interviews
   - Career guidance based on their profile

   Always be encouraging, specific, and actionable.
   Use the student data provided to give personalized advice.
   If you don't have enough data, ask the student for clarification.
   Never make up information — only use the data provided."

15. KNOWLEDGE BASE
================================================================================

The knowledge base powers the semantic search behind the AI chat assistant.
Staff upload documents (syllabi, notes, question papers, roadmaps, placement
guides), which are split into passages and embedded using nomic-embed-text.
When a student asks a question, the closest passages are found by cosine
similarity and included in the prompt.

--- HOW IT WORKS ---

  1. Staff uploads a document via POST /api/v1/kb/documents
     (or indexes a study material / interview question / question paper for AI)
  2. The document text is split into passages (chunks)
  3. Each passage is embedded using nomic-embed-text via Ollama
  4. Embeddings are stored as real[] arrays in PostgreSQL (no pgvector needed)
  5. When a student asks a question in chat:
     a. The question is embedded with the same model
     b. All passage vectors are compared by cosine similarity
     c. Passages below a minimum score (0.53) are dropped
     d. Passages scoring far below the best match are also dropped
     e. Top passages are included as context in the LLM prompt

--- DOCUMENT TYPES ---

  syllabus, notes, question_paper, placement, resume, roadmap, other

Documents can be scoped to a department (only students in that department see
them) or left unscoped (everyone sees them).

--- BUILT-IN KNOWLEDGE CONTENT ---

On first startup, the backend seeds built-in knowledge from markdown files in:
  backend/internal/modules/kb/knowledge/

These files contain curated content that is always available to the AI:

  career-paths.md      — Career roadmaps for common engineering roles
                         (Software Engineer, Data Scientist, etc.),
                         what each role does, required skills, typical paths
  domain-knowledge.md  — Domain-specific knowledge across engineering fields,
                         core concepts, industry applications
  industry-skills.md   — Industry skill requirements by sector, what companies
                         look for, technology trends, certifications

These files are embedded and indexed automatically in the background when the
server starts. To update them, edit the markdown files and restart the server.

--- AI INDEXING OF EXISTING RESOURCES ---

Study materials, interview questions, and question bank entries that have
uploaded files can be indexed for the AI knowledge base:

  POST /api/v1/study-materials/:id/index-for-ai
  POST /api/v1/interview-questions/:id/index-for-ai
  POST /api/v1/question-bank/:id/index-for-ai

This extracts text from the file, chunks it, embeds it, and stores it in the
KB so the chat assistant can cite it.

16. NEW AI-POWERED MODULES
================================================================================

--- APTITUDE TEST ---
Module: backend/internal/modules/aptitude/
Tables: aptitude_questions, aptitude_attempts (migration 000013, 000023)

Students take timed aptitude tests drawn from a question bank. Each attempt is
auto-scored. The summary endpoint returns best score, average, attempt count
and per-category breakdown. Used in the readiness score calculation.

Endpoints:
  GET  /api/v1/students/:id/aptitude          — Summary + history
  POST /api/v1/students/:id/aptitude/start    — Start a timed attempt
  POST /api/v1/aptitude/attempts/:id/submit   — Submit and score

--- COMMUNICATION REVIEW ---
Module: backend/internal/modules/talent/ (reviewCommunication handler)
Tables: communication_reviews (migration 000023)

Staff rate a student's communication on four criteria (1 to 5) using a rubric.
Students can also self-report via the communication questionnaire (assessment
kind = 'communication'). The latest staff review is used for the readiness
score.

Endpoint: POST /api/v1/students/:id/communication-review

--- PSYCHOMETRIC ASSESSMENTS ---
Module: backend/internal/modules/talent/
Tables: student_assessments (migration 000022, 000023)

Three questionnaire types: personality, interests, and learning style.
The questionnaire content is served from the backend (GET /assessments/
questionnaires/:kind). Each submission is stored; the latest per kind is
current, older ones form history.

Used by career fit analysis: personality matches career key_traits, interests
match the Holland code, and learning style guides resource recommendations.

--- CAREER FIT (Interests, Personality, Coding) ---
Tables: careers extended (migration 000024)

Careers now carry:
  holland_code       — 3-letter Holland interest code (e.g. RIA, SEC)
  key_traits         — Personality traits that fit the role
  coding_relevance   — 0.0 to 1.0 (how much the role relies on programming)
  growth_outlook     — 1 to 5 (indicative career growth potential)
  growth_note        — Free-text note about growth prospects

Career matches now include a "fit" JSON object showing how well the student's
assessments align with the career's requirements.

--- GROWTH OUTLOOK ---
Part of career fit (migration 000024). Each career has a growth_outlook score
(1-5) and a growth_note. Shown in the career cards and placement prep plan.

--- PLACEMENT PREP PLAN ---
Module: backend/internal/modules/career/
Tables: career_project_ideas (migration 000026)

A placement prep plan shows:
  - Skills the student needs to develop for a career
  - Recommended courses to fill gaps
  - Project ideas to demonstrate the required skills
  - Growth outlook for the career

Each career can have project ideas at three levels (beginner, intermediate,
advanced).

--- STUDENT INSIGHT (Overall Reading) ---
Module: backend/internal/modules/insight/
Tables: student_insights (migration 000025)

Generates an AI-powered "overall reading" of a student by gathering facts
from marks, skills, aptitude scores, assessment results, career matches and
attendance, then asking the LLM to summarize them into 2-3 sentences and
up to 3 next steps. A safety check rejects any model output that strays
beyond the provided facts. Falls back to a plain-text summary if the model
is unavailable or produces rejected output. Cached per student until their
underlying data changes (tracked by a facts hash).

Endpoint: GET /api/v1/students/:id/insight

--- DATA QUALITY REPORT ---
Module: backend/internal/modules/quality/
No new tables (reads existing data)

Scans the database for data completeness and anomalies:
  - Students missing marks, skills, CGPA, attendance, contact info
  - Mismatches and inconsistencies
  - Per-department breakdown

Available to admin, placement officers, HODs and staff. HODs and staff
see only their own department.

Endpoint: GET /api/v1/reports/data-quality?department_id=

--- FACULTY RISK ALERTS & SCORE HISTORY ---
Module: backend/internal/modules/faculty/
Tables: student_score_history (migration 000027)

The faculty readiness dashboard (GET /analyzer/readiness) returns all students
with:
  - Readiness score (composite of CGPA, skills, aptitude, coding, communication, attendance)
  - Risk level (high, medium, low)
  - Risk reasons (which components are dragging the score down)
  - Score change (compared to ~1 month ago)

A daily background loop takes a snapshot of every student's scores. When a
student newly becomes "high risk", an in-app notification is sent to relevant
staff. Staff can also trigger an immediate snapshot.

Endpoints:
  GET  /api/v1/analyzer/readiness          — Faculty readiness dashboard
  POST /api/v1/analyzer/snapshot           — Trigger immediate snapshot
  GET  /api/v1/students/:id/score-history  — Score history over time

--- BLOOM'S TAXONOMY ---
Module: backend/internal/modules/blooms/
No new tables (updates question_bank.blooms_level)

When staff add questions to the question bank, the LLM suggests the Bloom's
taxonomy level (Remember, Understand, Apply, Analyze, Evaluate, Create).
Staff can also review existing questions in batch and apply the suggested
levels.

Endpoints:
  POST /api/v1/blooms/suggest  — Classify a single question
  POST /api/v1/blooms/review   — Review a batch of existing questions
  POST /api/v1/blooms/apply    — Apply suggested levels to the question bank

--- SKILL SUGGESTIONS FROM MARKS ---

Analyzes a student's marks across subjects and proposes skill levels. The

  POST /api/v1/subjects/:id/skill-mapping/suggest         — Suggest skill mapping

18. TROUBLESHOOTING
================================================================================

Problem: "Cannot reach the server" on mobile app
  - Check backend is running: curl http://localhost:8080/health
  - Check your PC's IP: ipconfig (Windows) / ifconfig (Linux)
  - Rebuild APK with correct IP: flutter build apk --dart-define=API_URL=http://<CORRECT_IP>:8080/api/v1
  - Allow firewall: netsh advfirewall firewall add rule name="Skills Analyzer API" dir=in action=allow protocol=TCP localport=8080
  - Phone must be on same Wi-Fi as server

Problem: "Invalid username or password"
  - The admin password is set in .env (ADMIN_PASSWORD)
  - It only creates the admin on FIRST run when no admin exists
  - To reset: UPDATE users SET password_hash = '<bcrypt_hash>' WHERE username = 'admin';
  - Generate hash: python -c "import bcrypt; print(bcrypt.hashpw(b'newpassword', bcrypt.gensalt()).decode())"

Problem: Database migration errors
  - Check PostgreSQL is running
  - Check DATABASE_URL in .env is correct
  - Check the postgres user has permission to create tables

Problem: Port already in use
  - Kill the process: netstat -ano | findstr :8080
  - Then: taskkill /PID <pid> /F

Problem: CORS errors in browser
  - Add the frontend URL to CORS_ORIGINS in .env
  - Restart the backend

Problem: Ollama not responding
  - Check: ollama list (should show llama3.2 and nomic-embed-text)
  - Check: curl http://localhost:11434/api/tags
  - Restart: ollama serve

Problem: LLM responses are slow
  - Use a smaller model: ollama pull phi3
  - Add more RAM or a GPU
  - Set a shorter max_tokens in the API call

Problem: Knowledge base search returns no results
  - Check nomic-embed-text is pulled: ollama list
  - Check that documents have been uploaded or built-in content was seeded
  - The server seeds built-in content on startup; check logs for errors
  - Re-index documents: POST /api/v1/kb/documents (re-upload)

Problem: Student insight says "unavailable"
  - The insight module needs the chat model (llama3.2) running
  - If the model is down, insight falls back to plain-text facts
  - Check Ollama is running and the model is loaded

Problem: Bloom's / skill suggestions not working
  - These features need the chat model (OLLAMA_MODEL) running
  - Check OLLAMA_URL and OLLAMA_MODEL in .env
  - The model must be pulled: ollama pull llama3.2

Problem: Risk alerts not appearing
  - Risk alerts are generated by a daily background loop
  - To trigger immediately: POST /api/v1/analyzer/snapshot
  - Alerts are in-app notifications only (no email or SMS)
