## Industry skill: Data structures and algorithms
Companies use data structures and algorithms questions to see how you think, because the same ideas appear in real code. Know arrays, strings, linked lists, stacks, queues, hash maps, trees, graphs, sorting, searching, recursion and basic dynamic programming. Practise by topic, not at random: finish arrays and strings, then hash maps, then trees. After each problem, write down the time and space cost and a second way to solve it. Aim for steady practice, such as a few problems a day, rather than long bursts before interviews. Verified solved counts on coding platforms also count towards the programming index in this system.

## Industry skill: SQL and databases
SQL is asked in almost every software, data and testing interview. Learn SELECT with WHERE, GROUP BY and HAVING, the four join types, subqueries, aggregate functions, indexes, primary and foreign keys, normalisation and transactions. Practise by writing queries against a small database you design yourself, such as students, courses and marks. Be ready to explain why a query is slow and how an index helps. Knowing the difference between a join and a subquery, and between delete, truncate and drop, comes up often.

## Industry skill: Git and version control
Git records every change to code so that teams can work together and undo mistakes. Learn clone, add, commit, push, pull, branches, merge, resolving a conflict and reading the log. Use GitHub for every project, with clear commit messages and a README that says what the project does and how to run it. A tidy profile with regular commits is one of the easiest ways for a student to show real work. Interviewers often ask how you handled a merge conflict.

## Industry skill: Object-oriented programming
Object-oriented programming organises code around objects that combine data and behaviour. Know classes and objects, encapsulation, abstraction, inheritance and polymorphism, the difference between an interface and an abstract class, and overloading versus overriding. Be able to explain each with a small example from your own project. For design questions such as a parking lot or a library system, list the classes, what each one knows and does, and how they relate.

## Industry skill: Web and REST APIs
Most applications talk to each other through APIs. Understand HTTP methods (GET, POST, PUT, DELETE), status codes, JSON, headers, authentication with tokens, and what makes an API easy to use. Build a small API with a framework you like, add validation and error messages, test it with a tool such as Postman and document the endpoints. Know the difference between authentication (who are you) and authorisation (what may you do).

## Industry skill: Linux and the command line
Servers, cloud machines and many development tools run on Linux. Learn navigating folders, viewing and searching files, permissions, processes, installing software, environment variables, simple shell scripts and reading logs. Practise by setting up a virtual machine or using a cloud free tier and doing everyday tasks without a mouse. This is a basic requirement for cloud, DevOps, backend and embedded roles.

## Industry skill: Cloud fundamentals
Cloud platforms rent computing, storage and databases over the internet. Learn the main ideas rather than every service: virtual machines, storage, managed databases, networking and security basics, regions and pricing. Deploy a small app to one platform, such as AWS, Azure or Google Cloud, using the free tier carefully and always switching off what you start. A cloud fundamentals certification is a reasonable first credential for a student.

## Industry skill: Docker and containers
A container packages an application with everything it needs so that it runs the same on any machine. Learn what an image and a container are, how to write a simple Dockerfile, how to run several containers together and how to push an image to a registry. A good beginner project is to containerise your own web app and its database. Containers are common in backend, DevOps and cloud roles.

## Industry skill: Software testing basics
Testing shows whether software does what it should. Know the difference between unit, integration and system tests, how to write a good test case with steps and expected results, how to report a bug so that someone can reproduce it, and what regression testing is. Write automated tests for your own projects. Even developers are expected to test their own work, and testing roles also value SQL and some programming.

## Industry skill: Python for data
Python is the common language for data work. Learn core Python, then NumPy and pandas for handling tables, Matplotlib or a similar library for charts, and Jupyter notebooks for explaining your steps. Practise by cleaning a messy dataset: fixing missing values, wrong types and duplicates, and then answering questions with grouping and charts. Clean, well-explained notebooks make a strong portfolio.

## Industry skill: Machine learning fundamentals
Machine learning finds patterns in data to make predictions. Know supervised and unsupervised learning, training and test data, overfitting, common metrics such as accuracy, precision and recall, and a few models such as linear regression, decision trees and nearest neighbours. Always split your data, measure honestly and look at the mistakes. Learn the maths gradually: statistics, probability and linear algebra support everything else.

## Industry skill: Excel and business intelligence tools
Spreadsheets and dashboard tools are used in almost every company. Learn formulas, lookups, pivot tables, charts and data cleaning in Excel, and then a dashboard tool such as Power BI or Tableau. A student who can turn a messy sheet into a clear dashboard and explain it is useful in analyst, business and operations roles.

## Industry skill: Agile and teamwork in software projects
Most software teams work in short cycles called sprints and meet briefly each day to share progress and blockers. Know the roles of a product owner and a scrum master, what a user story and a backlog are, and how a sprint review works. Teamwork also means giving and receiving code review feedback politely, asking for help early and keeping others informed. Class projects done in a team are good places to practise and to talk about in interviews.

## Industry skill: Communication for technical roles
Communication is one of the most common reasons good candidates are rejected. Practise explaining a technical idea to a non-technical person in three sentences, structuring an answer as situation, action and result, writing a clear email and listening before answering. In group discussions, make one or two clear points and build on others rather than interrupting. Record yourself answering common questions and listen back. The communication score in this system comes from a staff rating plus your own self-assessment.

## Industry skill: Aptitude and logical reasoning
Many companies start with an aptitude test covering quantitative questions (percentages, profit and loss, time and work, speed and distance), logical reasoning (series, puzzles, seating arrangements) and verbal ability (grammar, reading and vocabulary). Speed matters, so practise under a timer and review every mistake. Learn shortcuts for common question types and keep a notebook of formulas. Even a short daily practice session makes a clear difference over a month.

## Industry skill: Building a resume and GitHub profile
A good student resume fits one page, starts with a short summary, lists skills you can actually discuss, then projects, internships, education and certificates. For each project write what it does, the technologies used and one result. Never list a skill you cannot answer questions on. Keep your GitHub projects tidy with README files, and make sure the links on your resume work. Ask a senior or a staff member to review it before applying.
